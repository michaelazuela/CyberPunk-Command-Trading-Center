# Agent Operating Guide

This repository is a MES/MNQ trading decision-support app. Future agents must preserve the existing architecture and avoid rule drift.

## Non-Negotiables

- Use Supabase and Cloudflare only.
- Do not add Firebase, Firestore, Firebase Auth, or Firebase Storage.
- Do not expose `GEMINI_API_KEY` in browser code, Vite env vars, localStorage, Supabase, or docs examples.
- Gemini API calls must go through the Cloudflare Pages Function at `/api/gemini`.
- The app is a decision-support system, not an automated trading or prediction tool.
- No-trade is a valid outcome.
- MES is the primary instrument. MNQ support must not break MES workflows.
- Dark mode is the primary UI mode.

## Execution Authority

Gemini may describe the chart and provide advisory context, but the app owns executable trade decisions.

- Advisory fields: `best_trade_plan`, `final_trade_plan`, `candidate_trade_plans`, and legacy suggested fields.
- Executable fields: the normalized app-owned plan generated by `src/lib/planEngine.ts` and `src/lib/tradePlan.ts`.
- Final executable targets must be deterministic:
  - T1 = 1.5R from ENTRY/STOP
  - T2 = 2.0R from ENTRY/STOP
- Do not show Gemini as the source of the executable trade plan UI.

## Session Types

Use the app-owned session types consistently:

- `morning`
- `lunch`
- `replay_morning`
- `replay_lunch`

Replay sessions must reuse the live rule engine for the matching live session while writing replay-specific RAG context.

## Canonical Time Windows

All trading windows must come from `src/config/timeWindows.ts`.

- Morning Analysis: 9:30 AM-11:15 AM ET.
- Required Morning screenshot range: 9:30 AM through the 10:10 AM candle.
- Lunch Reversal: 11:50 AM-1:00 PM ET.
- Required Lunch screenshot range: 11:50 AM-1:00 PM ET.
- Midnight Open is a core RAG feature, not temporary UI state.

Do not hardcode competing time strings in prompts, docs, UI text, or logic.

## 15M ETH Context

The 15M ETH Context screenshot is context only.

It may help identify ETH high/low, Asian high/low, London high/low, NY premarket high/low, overnight high/low, prior session high/low interaction, broader trend, compression/expansion, major support/resistance, and early RTH direction into 10:00 AM ET.

It must not approve a trade by itself, generate final entry/stop/T1/T2 by itself, override the 5M execution chart, override the plan engine, override the trade decision pipeline, override risk rules, or override setup scanner ranking.

The 5M chart remains the execution chart for entry trigger, active swing, stop placement, risk check, and final trade approval.

## RAG And Persistence

Every completed analysis and replay outcome should have a durable Supabase record and a RAG learning record when possible.

- Store image URLs, not base64 images.
- Save setup/trade metadata, normalized plan data, proof metadata, and save receipts.
- If embedding fails, preserve the base record and allow retry.
- RLS must keep user data scoped to `auth.uid()`.

