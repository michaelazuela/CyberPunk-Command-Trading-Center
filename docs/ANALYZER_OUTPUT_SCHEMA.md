# Analyzer Output Schema

This document defines the expected separation between analyzer output and app-owned trade decisions.

The analyzer may use AI to extract chart context. The analyzer must not be treated as the final trade authority. The deterministic app pipeline must produce the final executable trade plan.

## Output Layers

Analyzer output should be separated into four layers:

1. Chart observations
2. Advisory candidate context
3. App-owned decision fields
4. Journal/RAG persistence fields

## 1. Chart Observations

These fields describe what is visible or supplied.

```ts
interface ChartObservationOutput {
  sessionType: "morning" | "lunch" | "replay_morning" | "replay_lunch";
  instrument: "MES" | "MNQ";
  screenshotTimeframe?: "5m" | "15m" | string;
  screenshotTimestamp?: string | null;
  screenshotUsability: "usable" | "warning" | "unusable";
  screenshotWarning?: string | null;

  currentPrice?: number | null;
  midnightOpenPrice?: number | null;
  rthVsMidnight?: "above" | "below" | "at" | "unknown";

  openingRangeHigh?: number | null;
  openingRangeLow?: number | null;
  initialBalanceHigh?: number | null;
  initialBalanceLow?: number | null;

  ethHigh?: number | null;
  ethLow?: number | null;
  asianHigh?: number | null;
  asianLow?: number | null;
  londonHigh?: number | null;
  londonLow?: number | null;
  nyPremarketHigh?: number | null;
  nyPremarketLow?: number | null;

  visibleStructureSummary: string;
  extractedOcrText?: string | null;
}
```

## 2. Advisory Candidate Context

AI may return candidate observations, but these are not executable by themselves.

```ts
interface AdvisoryCandidate {
  setupName: string;
  ruleCategory?: string;
  direction: "LONG" | "SHORT" | "NO TRADE";
  observedEntry?: number | null;
  observedStop?: number | null;
  observedTriggerState?: "TRIGGERED" | "PENDING_TRIGGER" | "NO_TRIGGER";
  observedEntryTrigger?: string | null;
  confidence?: "High" | "Medium" | "Low";
  reason: string;
  invalidation?: string | null;
}
```

Advisory candidates may help the rule engine, but the app must still:

- Classify the setup
- Validate the entry trigger
- Validate the stop
- Hard-block risk
- Compute T1/T2
- Decide trade or no-trade

## 3. App-Owned Decision Fields

The final executable fields must come from the deterministic rule-based pipeline.

```ts
interface AppOwnedTradeDecision {
  source: "app_rule_engine";
  decision: "LONG" | "SHORT" | "NO TRADE";
  setupName: string;
  entry: number | null;
  stop: number | null;
  t1: number | null;
  t2: number | null;
  riskPoints: number | null;
  riskRewardT1: "1.5R" | null;
  riskRewardT2: "2.0R" | null;
  triggerState: "TRIGGERED" | "PENDING_TRIGGER" | "NO_TRIGGER";
  entryTrigger: string | null;
  canExecute: boolean;
  invalidation: string;
  whyThisPlan: string;
  rejectedAlternatives?: Array<{
    setupName: string;
    rejectionReason: string;
  }>;
}
```

## 4. Journal And RAG Fields

The saved record must be usable for trade review and future RAG learning.

```ts
interface JournalReadyRecord {
  planVersionId: string;
  setupSignature: string;
  sessionType: "morning" | "lunch" | "replay_morning" | "replay_lunch";
  instrument: "MES" | "MNQ";
  tradeDate: string;
  screenshotUrl?: string | null;
  proofScreenshotUrl?: string | null;
  normalizedPlanJson: AppOwnedTradeDecision;
  outcome?: "win" | "loss" | "scratch" | "no_trade" | "missed_trade" | "pending";
  ragSaved: boolean;
  saveReceiptJson?: Record<string, unknown>;
}
```

## Required Final Sequence

The output must support this fixed sequence:

1. Confirm session and instrument
2. Confirm screenshot usability
3. Identify market context
4. Identify key levels
5. Determine bias
6. Check approved time window
7. Identify setup type
8. Validate entry trigger
9. Validate stop location
10. Validate risk limit
11. Determine target model
12. Define invalidation
13. Decide trade or no-trade
14. Generate final trade plan
15. Save journal-ready record

## Authority Boundary

AI output is allowed to populate chart observations and advisory candidates.

The final executable decision must be generated by deterministic app code.
